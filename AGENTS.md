# Mixly Website — Project Workflow

## Linear is required for task tracking

Before starting any user-requested implementation, work through Linear:

1. If the user names an issue, open it first and use its scope and acceptance criteria.
2. Otherwise, search the Mixly Linear workspace for an existing relevant issue before making changes.
3. If no suitable issue exists, create one in the appropriate Mixly team/project before implementation. Include a concise title, context, scope, and acceptance criteria; avoid duplicates.
4. Keep implementation within the linked issue's scope. Report the Linear issue identifier and any unresolved acceptance criteria in the handoff.

Do not create, update, or close unrelated Linear issues.

## Linear status convention

- When the requested work is complete and targeted checks pass, move the linked issue to **In Review** (the team's review state; do not move it directly to Done).
- When work is blocked, requires clarification, or has unresolved follow-up questions, keep or move the issue to **In Progress** and record the blocker.

## Duplicate issue handling

- Before creating or starting an issue, compare its title, problem, scope, and acceptance criteria with existing Mixly issues.
- If it duplicates an existing issue, use the existing issue as the canonical task and merge any missing context, requirements, links, or evidence into it. Do not create parallel work.
- Keep the duplicate linked to the canonical issue for traceability; do not use the Duplicate workflow column for new cases.
